# hired Design Document

This document has moved. Its contents were a reworded copy of
[SPEC-HIRE.md](SPEC-HIRE.md) — same sections, same order, differing only in title case,
dash style and a handful of phrase swaps — so every correction had to be made twice
and the two had already drifted apart on spelling and punctuation.

**The architecture and technical design now live in [SPEC-HIRE.md](SPEC-HIRE.md).**

The filename is kept because the split it implied is still worth making, just not yet.
`SPEC-HIRE.md` currently holds both normative material — the SPIFFE ID schema, the trust
domain model, the assurance and presence definitions, the wire format — and material
that is context rather than specification, such as the Zero Trust stack components, the
build order and the coverage map. Separating those is worth doing when there is a
standards-body draft to separate them for, because that is the point at which what
counts as normative stops being a guess.
